## 二、六大主题深度分析

### 主题1：Agent 基础设施五层结构成形 🏗️ —— 本周一号主题

**核心论文**：ACG (A1), Choir (A3), FRAIL (A4)
**核心项目**：paperclip, orca, ax, hindsight, laya（7 个入选项目中 5 个）

**联动分析**：
W39 我们记录了 Harness 三层结构的清晰化；W40 完成体出现了：**执行 → 编排 → 组织管理 → 记忆 → 决策，五层本周各有一个标志性项目**——执行层由既有 CLI Agent 占据（orca 兼容 25+ 种），编排层 google/ax（声明式 YAML 三原语 + kubectl 心智模型），组织管理层 paperclip（任务分配/预算控制/审计留痕），记忆层 hindsight（重要性/合并/衰减/淘汰四杠杆），决策层 laya（33ms 单次前向，零 token 成本）。

论文侧罕见的同步：三层都有对应理论到货。**编排层 ↔ Choir**（分布式协作的协议形态）、**记忆层 ↔ ACG**（状态维护的一致性图）、**组织管理层 ↔ FRAIL**（个体理性到集体崩溃的稳定化机制）。三篇论文不是碰巧同周出现——当工程侧把每一层都立起标杆，学术侧的对应问题自然就浮出水面了。

最值得注意的是两种"多 Agent 组织哲学"的同周对撞：Choir 走**协议路线**（开放协议、可扩展性优先、三大证明助手生态），ax 走**运行时路线**（声明式原语、沙箱隔离、检查点恢复）。互联网的 TCP/IP 与 Kubernetes 的 Deployment/Service 当年也是这两种思路，最后分层共存。Agent 基建大概率重演：**协议层归协议，运行时归运行时**。

**趋势判断**：五层结构的下一战是层间接口标准化（记忆层 ↔ 编排层的 API、决策层 ↔ 执行层的调用约定）；3 个月内会出现"五层全栈"的集成项目；"Agent 操作系统"叙事将在 Q4 取代"Agent 框架"。

### 主题2：长 horizon 状态维护与记忆巩固 🧠 —— "记什么"与"怎么记"会师

**核心论文**：ACG (A1)，关注级 Stale-Doc Poisoning (C2)
**核心项目**：hindsight, paperclip

**联动分析**：
论文短名单自己的核心判断 #1 说得准：长 horizon Agent 的"状态维护"成为关键战场，ACG / CAIRN / IntentFlux 从互补角度切入同一问题——**Agent 能走多远，比 Agent 能多快更根本**。

工程侧的呼应精准得近乎排练：hindsight 的"记忆需要巩固"（从 RAG 的检索即记忆，升级为重要性/合并/衰减/淘汰四杠杆）回答"怎么记"，ACG 的一致性图回答"记什么、以什么一致性级别记"。两者结合才是完整答案——**只巩固不筛选，Agent 被陈旧记忆拖死（Stale-Doc Poisoning 翻转 30-75% 答案就是这个故障模式）；只筛选不巩固，Agent 永远从零开始**。

paperclip 的行为日志/审计留痕是第三条腿：长期任务不仅需要记住事实，还需要能回溯"当时为什么这么决策"——ACG 的一致性图本质上维护的正是这种可回放状态。

**趋势判断**：记忆系统评测将出现"遗忘正确性"维度（该忘的忘掉、不该忘的留住）；Agent 记忆 poisoning 进入威胁模型手册；长任务执行轨迹（谁决策、何时、基于什么状态）成为新的高价值数据资产。

### 主题3：推理效率：从压缩到翻译，从生成到判定 ⚡

**核心论文**：CoWindow (B1), KV-Lingo (B2), SphereGate (B3)
**核心项目**：laya, orca, ax

**联动分析**：
论文侧的效率研究重心本周确认转移：不再问"怎么删"（压缩），而是问"怎么跨模型、跨头复用"（翻译/共享）。KV-Lingo 的跨模型 KV 翻译让**模型切换从冷启动变热切换**——这对 orca（25+ CLI Agent 并行）和 ax（多 provider Model 原语）是直接可接的组件：动态路由架构（小模型先处理、大模型接管）的最后一块工程拼图。

CoWindow 的"全因果覆盖是集体属性"则提供了另一条路：不必每个 head 都覆盖全部历史，头间互补即可——128K 训练 7.4x 加速而 scaling law 几乎无损。如果可复现，注意力架构的"全员全因果"默认假设就被打破了。

最激进的效率答案来自工程侧：laya 干脆不生成——单次前向 33ms 做类型化判定，零 token 成本，typed-decisions 0.766 反超自回归的 Jev 0.727。**"生成更便宜"（CoWindow/KV-Lingo）与"干脆不生成"（laya）两条路线本周同榜，Agent 双系统架构（System 1 判定 + System 2 生成）有了两端的现成组件。** SphereGate 从机制侧给了统一解释：0.1M 参数门控超过全模型 GRPO，说明大模型内部本来就有可供小模块接管的结构化子空间——小模块有效不是巧合，是结构。

**趋势判断**：模型路由（大小模型协同）因 KV-Lingo 类技术从研究课题变为工程选项；决策引擎（System 1）成为 Agent 流水线的标准可插拔组件；"效率优化对准 Agent 负载"继 W39 的 DeepSeek-V4.1-Flash 后连续第二周被验证为研究主航道。

### 主题4：多 Agent 社会经济学 💥 —— 从"怎么协作"到"怎么不崩"

**核心论文**：FRAIL (A4), Choir (A3)
**核心项目**：paperclip, orca, ax

**联动分析**：
多 Agent 研究的重心本周从"协作"正式扩展到"社会"。FRAIL 把 LLM Agent 放进三种动态金融环境（银行挤兑、债务滚动、奖励众筹），发现**个体理性的 Agent 无需恶意指令就能引发集体崩溃**——基线银行挤兑失败率 77%。更值钱的是稳定化机制的比较结论：三种机制（补偿承诺、集中承诺协议、参与者联盟）成功时共享同一个时序模式——**广泛承诺必须在防御行为自我强化之前形成**。

这个时序结论对工程侧是直接的：paperclip 的预算控制与审批路径、ax 的 Task 资源限额、`ax suspend/resume` 检查点，都是"防御行为"的基础设施——它们必须在 Agent 社群学会自我保护性封盘/停工之前配置好，否则就是挤兑的数字化重演。

Choir 从另一侧补充：分布式形式化用开放协议把"信任"问题转化为"协议遵守"问题——数学证明可机械验证，所以协议化可行。**FRAIL 与 Choir 合起来就是多 Agent 社会的两条治理路线：经济学路线（承诺与激励）与协议学路线（验证与合规）**。

**趋势判断**：Agent 劳动力管理（hiring/firing/budgeting 一组 Agent）成为新的产品品类；多 Agent 系统的"压力测试"（模拟挤兑/级联故障）将进入部署 checklist；多 Agent 经济仿真环境（FRAIL 的三种环境）预计出现开源复刻。

### 主题5：后训练机制理解爆发 🔬 —— 一个可直接操作却仍未被理解的空间

**核心论文**：SphereGate (B3), BSD (B4)，关注级 Alignment Paradox (C3)
**核心项目**：laya, open-code-review

**联动分析**：
本周入选论文里三篇（SphereGate/BSD，加关注级 Alignment Paradox）指向同一个元问题：**后训练在内部到底做了什么，我们仍然很浅**。SphereGate：各向异性不是缺陷是分工——5% 相干基底通道（移除后 PPL 从 10 涨到 10⁶）被 SFT 重塑、被 RL 保持不动。BSD：模型携带可提取、可写入的隐式用户信念，跨模型共享表示几何。Alignment Paradox：后训练对齐使高置信错误增加 10-35 倍。

工程侧的两种回应已经提前存在，只是不自知：laya 把"后训练"压缩成对小模型判别头的微调（绕开黑箱，用结构化的 System 1 层），open-code-review 用确定性管线兜住 LLM 的自信输出。**Alignment Paradox 的发现给了"确定性优先"哲学一个严格的理论注脚：对齐提升的是置信度校准的表观，不是正确率本身——那么凡是要求高正确率的环节，都应该有确定性组件兜底。**

安全含义同样直接：BSD 证明"写入用户信念"即可改变安全拒绝——**记忆系统（hindsight 类）写入用户画像的那一刻，就成了行为操控面**。这和主题2 的 Stale-Doc Poisoning 合起来，划定记忆层安全的两个基线问题：防篡改（poisoning）与防操控（belief writing）。

**趋势判断**：post-training 机制研究（子空间分工/信念几何）与 Agent 工程将互相供血；"用户模型"从推荐系统概念变成 LLM 的内部状态概念，隐私讨论将重启；对高置信错误的运行时探测（激活层）出现工具化。

### 主题6：确定性工程 × Agent 混合架构 🛠️

**核心论文**：ScopeIF (A2)，关注级 Decomposition Tax (C1)
**核心项目**：open-code-review, univer, ax
