**联动逻辑**：这是本周最"恰逢其时"的联动——K3.1 Pro 权重落地把"1M 上下文怎么跑得起"从理论问题变成账单问题，LSA 恰好给出答案：**10M token 预填充 22.7× 加速，且 SGLang 插件 day-0 可装**。vLLM/SGLang 对 K3.1 Pro 的 day-0 支持 + LSA 的 SGLang 插件 = "模型→插件→加速"的落地链路在本周闭合。ZHA 虽未放码，但与 LSA 的方法论趋同意味着这个方向的技术风险已被双路验证。**2.8T 参数 × 1M 上下文 × 亚二次注意力——三个条件第一次在同一个日历周内同时具备。**

**论文侧**：RoboArchitect（24 分，A类🏆，Stanford）证明编码模型观察 rollout 即可为**冻结的机器人策略**自动进化 harness——成功率从 9.7% 提到 43.3%；Mage-VL-Cowork（23 分，A类🏆）的"进化 harness 蒸馏"让 4B 模型在 OSWorld-Verified 上达 66.0%。

**联动逻辑**：**两篇论文独立验证了同一件事：agent 能力上限不在模型权重里，在围绕它的工程结构里。**RoboArchitect 的学术证明（冻结策略 + 自动 harness = 4.5× 成功率）恰好是 ECC 社区实践的学术镜像——ECC 的 296K 星不是偶然，是"手艺活系统化"需求的直接反映。Mage-VL-Cowork 的"进化 harness 蒸馏"方法论如果应用到 ECC 的 skill 生成流程，可能实现"ECC 用进化自动生成新 skill"的元循环。**harness 工程从"调参手艺"到"系统工程"到"自动进化"，三级跳在本周完成学术闭环。**

### 主题 3：Agent 安全从"论文"到"武器库"

**论文侧**：SecPO（23 分，A类🏆，UC Berkeley）用对抗训练防御提示注入，AgentDojo ASR 从 78.8% 降至 8.8%，且实用性不降。核心意义不在于方法本身，而在于**代码 + 训练数据 + 防御模型三箭齐发**——agent 安全研究从"证明问题存在"正式转向"提供可用工具"。

**开源侧**：ECC 的 AgentShield 安全扫描模块持续迭代；claude-mem 的持久记忆引入了新的攻击面——压缩后的语义摘要可能成为间接提示注入的载体；Lightpanda 的无头浏览器是 agent 与 Web 交互的边界层，其 CSP/安全策略直接影响 agent 的网页操作安全性。

**联动逻辑**：SecPO 的对抗训练 pipeline 解决"模型出厂安全"，ECC AgentShield 解决"部署运行安全"，claude-mem 类记忆系统需要解决"跨会话持久安全"——三个层面分别对应 SecPO 论文的代码/数据/模型三件套。**Agent 安全的三层防线在本周第一次同时拥有了论文级方法论和工程级实现。**特别值得注意：AgentDojo ASR 78.8%→8.8% 的下降幅度意味着之前的 agent 几乎不设防——这与 K3.1 Pro 等模型在 Terminal-Bench 上刷高分形成张力：**能力越强，被注入后的破坏力越大。**

### 主题 4：Agent 上下文效率的双路径收敛

**论文侧**：ASTC（22 分，A类🏆，MIT 协议）免训练利用 GDN 循环动态压缩 agent 上下文，减少 50.68% 注意力对——关键在**免训练**，即插即用；LSA（24 分）从注意力机制层面减少计算量；Flide（19 分，C类）用 ForkAttention 为决策模型做专用推理引擎。

**开源侧**：claude-mem 用 AI 压缩跨会话上下文（SQLite + Chroma 本地存储）；FreeToken 从 MoE 调度层面压榨硬件效率；ECC 的 hooks 模块做工具调用压缩。

**联动逻辑**：**"上下文膨胀"是 agent 从单次调用进化为多步执行后不可避免的问题**，解决方案正在分化为两条路径：ASTC 代表的"会话内压缩"（免训练、即时生效）和 claude-mem 代表的"跨会话持久化"（记忆注入新会话）。两条路径不是竞争而是互补——ASTC 管单次会话的 token 预算，claude-mem 管跨会话的知识传递。在 1M 上下文时代，"记什么、忘什么、何时查"的决策仍然关键——**窗口变大不等于记忆问题消失，原始上下文的成本与延迟使智能压缩反而更重要**。Flide 的 ForkAttention 若开源，可能为决策模型类 agent（如 ECC 的 tool-use router）提供第三个优化维度。

### 主题 5：GUI Agent × 浏览器基础设施的分层

**联动逻辑**：Mage-VL-Cowork 类 GUI agent 要在真实网页上执行任务时，浏览器的性能、成本和可控性是瓶颈。Chrome headless 为人类调试设计，Lightpanda 为"一百个 agent 同时操作一百个页面"设计。**当 4B 模型都能做到 66% OSWorld 时，限制 agent 规模化部署的不再是模型能力，而是浏览器层的吞吐量和成本**——Lightpanda 的 140 并发实例 × 11× 速度 × 9× 内存节省恰好解除这个瓶颈。K3.1 Pro 作为多模态基座，理论上可以替代 Mage-VL-Cowork 的私有基座做更大规模的复现——**"开放权重基座 + 高性能浏览器层 + 进化 harness"的三件套是 GUI agent 从论文走向产品的最短路径。**
