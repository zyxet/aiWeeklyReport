## 二、主题分类

### 🔬 主题 A：超长上下文注意力 × 推理基础设施（本周最强联动）

**论文侧**：LSA（24 分🏆）隐空间层次聚类实现亚二次注意力，10M token 预填充加速 22.7×，生产级模型实测（GLM-5.3-Flash / Qwen3.8-27B）；ZHA（21 分）树索引从另一方向抵达同一结论，支持数亿 token。

**开源侧**：K3.1 Pro 权重 11-04 落地 HF（2.8T MoE / 1M 上下文）；FreeToken 把 290B+ MoE 搬到消费级显卡。

**联动逻辑**：K3.1 Pro 落地把"1M 上下文怎么跑得起"从理论问题变成账单问题，LSA 恰好给出答案——10M token 22.7× 加速且 SGLang 插件 day-0 可装。vLLM/SGLang day-0 支持 + LSA 插件 = "模型→插件→加速"的落地链路在本周闭合。**2.8T 参数 × 1M 上下文 × 亚二次注意力——三个条件第一次在同一个日历周内同时具备。**

### 🔬 主题 B：Harness 工程三级跳——从手艺活到自动进化

**论文侧**：RoboArchitect（24 分🏆，Stanford）证明编码模型观察 rollout 即可为冻结机器人策略自动进化 harness，成功率 9.7%→43.3%（4.5×）；Mage-VL-Cowork（23 分🏆）用"进化 harness 蒸馏"让 4B 模型达 OSWorld-Verified 66.0%。

**开源侧**：ECC（296,684 ⭐，9 个月）作为"Agent Harness OS"，67 agents / 281 skills / 94 command shims，把"如何调教 agent 工具链"从手艺活变成系统工程。

**联动逻辑**：**两篇论文独立验证了同一件事：agent 能力上限不在模型权重里，在围绕它的工程结构里。**RoboArchitect 的学术证明恰好是 ECC 社区实践的学术镜像。如果 Mage-VL-Cowork 的进化 harness 蒸馏应用到 ECC 的 skill 生成流程，可能实现"ECC 自动进化新 skill"的元循环。

### 🔬 主题 C：Agent 安全从"论文"到"武器库"

**论文侧**：SecPO（23 分🏆，UC Berkeley）对抗训练防御提示注入，AgentDojo ASR 78.8%→8.8%，实用性不降。**代码 + 训练数据 + 防御模型三箭齐发**——agent 安全研究从"证明问题存在"正式转向"提供可用工具"。

**开源侧**：ECC AgentShield 安全扫描持续迭代；claude-mem 的持久记忆引入新攻击面（压缩语义摘要可能成为间接注入载体）；Lightpanda 是 agent 与 Web 交互的边界层。

**联动逻辑**：SecPO 解决"模型出厂安全"，AgentShield 解决"部署运行安全"，记忆系统需要解决"跨会话持久安全"——三个层面分别对应 SecPO 的代码/数据/模型三件套。AgentDojo ASR 78.8%→8.8% 意味着此前 agent 几乎不设防——**能力越强，被注入后的破坏力越大。**

### 🔬 主题 D：Agent 上下文效率双路径收敛

**论文侧**：ASTC（22 分🏆）免训练 GDN 循环动态压缩，-50.68% 注意力对，AppWorld 可复现；Flide（19 分）ForkAttention 决策模型推理引擎，比 vLLM/SGLang 快 9.5×。

**开源侧**：claude-mem 用 AI 压缩跨会话上下文（SQLite + Chroma）；FreeToken 从 MoE 调度压榨硬件效率。

**联动逻辑**：**上下文膨胀是 agent 多步化后不可避免的问题**，解决方案分化为两条互补路径：ASTC 的"会话内压缩"（免训练、即时生效）+ claude-mem 的"跨会话持久化"（记忆注入新会话）。在 1M 上下文时代，智能压缩反而更重要——**窗口变大不等于记忆问题消失**。

### 🔬 主题 E：GUI Agent × 浏览器基础设施分层

**论文侧**：Mage-VL-Cowork（23 分🏆）4B 混合 agent 达 OSWorld-Verified 66.0%，完整训练配方公开——证明小模型 + 进化 harness 蒸馏可以逼近大模型。

**开源侧**：Lightpanda（41,183 ⭐）Zig 无头浏览器，11× 快 9× 省，140 并发实例，原生 MCP/CDP/BiDi；K3.1 Pro 双模态输入为 GUI agent 提供开放权重基座。

**联动逻辑**：当 4B 模型都能做到 66% OSWorld 时，限制 agent 规模化的不再是模型能力，而是浏览器层的吞吐量和成本。Chrome headless 为人类调试设计，Lightpanda 为"一百个 agent 同时操作一百个页面"设计。**"开放权重基座 + 高性能浏览器层 + 进化 harness"是 GUI agent 从论文走向产品的最短路径。**

### 🔬 主题 F：效率即主线——垂直基座与专用推理栈

**论文侧**：Flide（19 分）为决策模型做专用推理引擎，ForkAttention 比通用栈快 9.5×；LSA/ASTC/ZHA 从注意力/上下文/机制三个层面提效。8 篇入选中 5 篇核心贡献直接与推理效率相关。

**开源侧**：Kronos（46,608 ⭐，28 天 +20.2k）首个金融 K 线开源基座（AAAI 2026），BSQ tokenizer + 自回归预训练；FreeToken 消费级 MoE 推理；hallmark 用规则约束生成空间。

**联动逻辑**：**"更快"和"更省"已不再是优化目标，而是产品可行性的前提。**Flide 代表新趋势——为特定模型类做专用推理栈，与 vLLM/SGLang 通用路线互补。Kronos 说明基座模型垂直化正从代码扩展到金融时序——通用基座能力边际递减时，"小基座 + 领域预训练"成为新的差异化路径。hallmark 从质量维度验证同一逻辑：规则约束比自由生成更高效。
